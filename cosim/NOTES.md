## Step 1 (RTL provenance and register map)

**The RTL was NOT generated on this laptop.** Vitis HLS is not installed here. The IP package
`m0_hls_package.zip` was generated by Janith (P1) with **Vitis HLS / vitis-run v2024.1 (SW Build 5069499, May 21 2024)**
from repo commit **07badc4** (his `commit.txt`; same as `origin/main` here). Checked from his `hls.log`:
C-sim `564 vectors, 0 mismatches -> PASS`, `CSim done with 0 errors`, part xc7z020clg400-1, clock period 10 ns,
`export_design` finished and created `xilinx_com_hls_qmlp_m0_1_0.zip`, no ERROR lines.
The zip contains `hdl/verilog` (127 `.v`, 118 `.dat` ROM files), `hdl/vhdl`, `drivers/qmlp_v1_0/src/xqmlp_hw.h`,
`component.xml`, `hls.log`, `commit.txt`. Extracted read-only to `~/m0_pkg`, copied to
`hw/hls/build/m0/proj_m0/sol1/impl/ip` (gitignored via `hw/hls/build/`). Verilog and `xqmlp_hw.h` were copied into
`cosim/rtl` and `cosim/include`.

Top module `qmlp`, clock `ap_clk`, active-low reset `ap_rst_n`, one AXI4-Lite slave `s_axi_ctrl_*`, plus `interrupt`.
Address width 7 bits (0x00-0x7F), data width 32. Protocol `ap_ctrl_hs`.

| Offset | Register | Notes |
|--------|----------|-------|
| 0x00 | AP_CTRL | bit0 ap_start (R/W, clears on handshake), bit1 ap_done (clear on read), bit2 ap_idle, bit3 ap_ready (clear on read), bit7 auto_restart, bit9 interrupt |
| 0x04 | GIE | bit0 global interrupt enable |
| 0x08 | IER | bit0 ap_done, bit1 ap_ready |
| 0x0c | ISR | bit0 ap_done, bit1 ap_ready (toggle on write) |
| 0x10 | SCORE_DATA | score[31:0], read; treat as signed int32 |
| 0x14 | SCORE_CTRL | bit0 score_ap_vld (clear on read) |
| 0x20 | ATTACK_DATA | attack[7:0] |
| 0x24 | ATTACK_CTRL | bit0 attack_ap_vld |
| 0x30 | MODEL_ID_DATA | model_id[31:0] |
| 0x34 | MODEL_ID_CTRL | bit0 model_id_ap_vld |
| 0x40-0x7F | X | 61 bytes; word n (at 0x40+4n) = x[4n] | x[4n+1]<<8 | x[4n+2]<<16 | x[4n+3]<<24 (little-endian). 16 words; word 15 holds x[60] in its low byte |

Offsets match `XQMLP_CTRL_ADDR_*` in `cosim/include/xqmlp_hw.h`.

## Step 4: Check R (m0 RTL alone in Verilator)

Testbench `cosim/tb/tb_axil.cpp`: holds `ap_rst_n` low for 20 clocks, then drives `s_axi_ctrl_*` with real AXI4-Lite
handshakes (VALID/READY sampled before the rising edge, VALID dropped after acceptance, waits for BVALID/RVALID,
timeouts everywhere). Offsets come from `xqmlp_hw.h`. For each line of `hw/hls/build/m0/vectors.txt` it writes the 61
bytes as 16 little-endian words, writes 1 to AP_CTRL, polls ap_done, reads SCORE (signed int32), ATTACK, MODEL_ID and
compares with the expected score, `attack = score > 1` and model id 0.
It must provide `double sc_time_stamp()` (the HLS RTL uses `$time`), otherwise linking fails.

```bash
cd cosim/rtl
verilator --cc --exe --build -Wno-fatal --top-module qmlp -CFLAGS "-I$PWD/../include" *.v ../tb/tb_axil.cpp -o tb_axil
./obj_dir/tb_axil ../../hw/hls/build/m0/vectors.txt
```
(Verilator 4.038 supports `--build`. Run from `cosim/rtl` so `$readmemh` finds the `.dat` files.)

Result (`cosim/logs/checkR.txt`):
```
AP_CTRL after reset = 0x00000004 (ap_idle bit2 set)
564 vectors, 0 mismatches (193479 clock cycles) -> PASS
```
About 343 clock cycles per record. Passed on the first run after the `sc_time_stamp` link fix.

Negative controls (so the PASS is not vacuous): changing the expected score of vector 1 by +1 gives
`1 mismatches -> FAIL`; replacing vector 2's input with all 255 gives got score=-8 vs expected -20, `FAIL`.
(Changing only x[1] of vector 1 did not change the score, which just means that byte does not affect that result.)
This confirms the register map, the byte packing, ap_start/ap_done handshake and signed score readout.

## Step 5: SystemC program with the m0 IP

`cosim/sc/ids_cosim.cc` = `zynq_demo.cc` with: debug device removed; `Vqmlp` (Verilated RTL, `--sc --pins-bv 2`) behind
`tlm2axilite_bridge<7,32>` via the library's `AXILiteSignals<7,32>` helper (as in
`libsystemctlm-soc/tests/example-rtl-axi4lite`), mapped with `bus.memmap(0x43C00000, 0x10000-1, ADDRMODE_RELATIVE, -1, bridge.tgt_socket)`
exactly like the demo mapped its debug device. `sc_clock` (see Step 6: 10 us period, not 100 MHz), active-low `rst_n` low for 20 cycles (also drives the bridge's
`resetn`), VCD `ids_cosim.vcd`. Build: `cd cosim/sc && ./build.sh ~/systemctlm-cosim-demo` (log `cosim/logs/sc_build.txt`).
Run: `cosim/sc/run.sh unix:/tmp/cosim/qemu-rport-_cosim@0 100000`. See `cosim/sc/README.md`.

Things that bit / are worth knowing:
- Verilator renames the port `interrupt` to `__SYM__interrupt` (reserved C++ word), so the connection uses that name.
- With Verilator 4.038 `Vqmlp.mk` does not build `verilated.o` by default: `build.sh` makes the targets `Vqmlp__ALL.a verilated.o`.
- ROM `.dat` files are opened relative to the current directory, so the program must be started from `cosim/rtl` (`run.sh` does that).
- The IP decodes 7 address bits; the bridge truncates wider addresses, so offsets 0x80-0xFFFF alias onto 0x00-0x7F.
- Smoke test: starting `ids_cosim` with no QEMU elaborates without errors and waits for the socket.
  (The decisions below were made while doing Check B.)

## Step 6: Check B (`devmem 0x43C00000 32` from Linux)

Boot exactly as in Check A, but start `cosim/sc/run.sh unix:/tmp/cosim/qemu-rport-_cosim@0 100000` instead of `zynq_demo`.
Result (`cosim/logs/checkB.txt`): `sudo devmem 0x43C00000 32` -> **0x00000004** (ap_idle set). The SystemC log has no
`DECODE ERROR` lines and the VCD shows exactly one AXI transaction after reset: that read.

Three problems on the way, all fixed in `ids_cosim.cc` (the RTL was fine each time):

1. **Boot never finished with a 10 ns PL clock.** `ids_cosim` sat at 100% CPU, QEMU idle, no console output for 10 minutes.
   Cause: with `-sync-quantum 100000` ns SystemC must simulate 10,000 RTL clock cycles (Verilator eval + trace) per quantum,
   and `-icount 7` makes the boot span hundreds of simulated seconds. Fix: PL clock period 10 us (`QMLP_CLK_NS`, as Xilinx's
   `zynqmp_demo` uses). **Consequence: the simulated clock is 10 us, not the 100 MHz HLS target.** One inference is about
   343 clock cycles = ~3.4 ms of simulated time. Cycle counts are valid, wall-clock timing is not claimed.
2. **VCD grew to 18 GB in ten minutes** (about 28 MB/s) because the demo's `trace()` dumps the whole Zynq model and the
   clock. Caught at 25 GB free disk, process killed, file deleted. Now only rst_n and the AXI-Lite signals are traced (they
   change only on real activity; the file is a few KB). The clock is added only with `IDS_COSIM_VCD_CLK=1` for short runs.
3. **First read gave 0x81 (ap_start + auto_restart set, ap_idle clear) instead of 0x4.** The VCD showed two writes at ~35 s of
   simulated time (before login): `0x00000000` then `0xFFFFFFFF`, both at register offset 0. The SystemC log had
   `DECODE ERROR! 41200000` and `...41204`. The image's device tree has an AXI GPIO node at 0x41200000 (original design) and
   the Linux GPIO driver writes data=0 and tri=0xFFFFFFFF at boot. `iconnect::map_address` sends every unmapped address to
   **target 0 at offset 0**, and the IP was target 0, so those writes hit AP_CTRL. Fix: a `memory` stub mapped first at
   0x41200000 (so it is target 0 and absorbs all decode errors). Side result: the IP follows its documented behaviour
   (writing 0 to AP_CTRL gave 0x0E = done|idle|ready, then 0x04 as done/ready cleared on read).

Caveats: addresses 0x80-0xFFFF inside the IP's window still alias onto 0x00-0x7F (7-bit decode in the IP/bridge).

## Step 7: Check C (every canary record through the simulated hardware)

`cosim/linux/cosim_test.py` (Python 3 + NumPy only; 5 KB). It `mmap`s 0x10000 bytes of `/dev/mem` at `--base`, uses real 32-bit
word loads/stores (`memoryview(...).cast('I')`, because ap_done is clear-on-read and byte-wise slices could misbehave), prints AP_CTRL,
and for each canary record writes the 61 bytes as 16 little-endian words, writes 1 to AP_CTRL, polls ap_done with a timeout, then reads
SCORE (signed), ATTACK, MODEL_ID. Expected values come from `qmlp.py` (the integer reference) run on `m0.npz`; in the canary file `y`
is only a 0/1 label (94% agreement with the model), not a score. It only touches offsets 0x00-0x7f.

Laptop first (`--simulate`: a Python stand-in that follows the register map and recomputes the score from the words written):
64/64 MATCH; with `--corrupt` 64/64 MISMATCH -> FAIL, so the compare path works. Then in the guest.

Getting files into the guest: no scp. The running image already contains `/opt/ids/{qmlp.py,pool-factory/{m0.npz,canary.npz,manifest.json}}`
with sha256 identical to the repo copies (compared on both sides, see `cosim/logs/checkC.txt`), so only `cosim_test.py` was pasted:
tmux `load-buffer`/`paste-buffer` in 18-line `cat >> /tmp/cosim_test.py <<'EOF_CT'` chunks, 6 s apart. Guest copy: 108 lines, sha256
`0c7978de768ab8349fcd9162e089be57b5ac6718527d0d7f057e4f7c25c562a5`, identical to the laptop.

```bash
# guest (after login; root is read-only, script is in /tmp)
cd /tmp && sudo python3 cosim_test.py --base 0x43C00000 --canary /opt/ids/pool-factory/canary.npz
```
Result (`cosim/logs/checkC.txt`): AP_CTRL = 0x4 before the run; **64 records, 64 match, 0 mismatch -> PASS**. Scores range from -22 to
17 (26 distinct values; 30 attack and 34 non-attack records); 2 polls per record. A 3-record trial took
1 m 06 s mostly for Python/NumPy start-up under `-icount 7`; the 64-record run finished in under 10 minutes of wall time (not timed precisely).
No `DECODE ERROR` in the SystemC log, VCD 250 KB.

### What this does and does not show
m0's RTL, generated by Vitis HLS (by Janith/P1, not on this laptop), was driven by Linux code running in QEMU through Xilinx's
remote-port co-simulation and matched the Python reference bit for bit on all 64 canary records.

`fpgautil` are untested. `app/appliance/fpga_regs.py` (UIO path, `score()` loop) has not been run; `cosim_test.py` uses `/dev/mem`
directly. Only m0 was simulated, not m1..m5. Nothing here checks the daemon (`idsd.py`) on `BACKEND=fpga`.
